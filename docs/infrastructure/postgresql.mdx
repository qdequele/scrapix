# PostgreSQL

The engine persists job history and engine-job results (batch scrapes,
extractions) through `DATABASE_URL`. This is a small, engine-owned schema
(`jobs`, `job_results`) — not the multi-tenant accounts/billing schema the
hosted platform uses (see PostgreSQL in the Platform docs for that one).

<Note>
  PostgreSQL is **optional** for a self-hosted engine. Without it (the
  default), job history is stored in a local SQLite file — durable across
  restarts, but only on that one machine. See
  [Self-Hosting → Durability](/deployment/self-hosting#durability) for what
  this does and doesn't survive.
</Note>

## Default: SQLite

If `DATABASE_URL` is unset, the engine uses
`sqlite://./data/scrapix.db` (the Docker images default to
`sqlite:///data/scrapix.db`, an absolute path under the `/data` volume). No
setup is required — the engine creates the file and applies its own
migrations (tracked in `_sqlx_migrations`, source at
`bins/scrapix-api/migrations/sqlite`) on startup.

## Optional: A Dedicated Postgres

Set `DATABASE_URL` to a `postgres://` or `postgresql://` URL to use Postgres
instead of SQLite — useful if you already run Postgres, want a shared job
store across multiple engine replicas, or want managed backups.

```bash
export DATABASE_URL=postgres://scrapix:scrapix@localhost:5433/scrapix
```

The engine applies its own migrations (`bins/scrapix-api/migrations/postgres`,
tracked in `_sqlx_migrations`) the same way it does for SQLite. This
**must** be a database dedicated to the engine — startup checks for a
`schema_migrations` table (the Rails app's migration tracking table) and
refuses to start if it finds one, to avoid two independently-migrated
schemas colliding in the same database:

```
DATABASE_URL points at a Rails (hosted) database; set SCRAPIX_MODE=hosted,
or give standalone a dedicated database
```

If you're running the hosted platform instead of self-hosting, set
`SCRAPIX_MODE=hosted` and point `DATABASE_URL` at the Rails-owned Postgres —
see PostgreSQL in the Platform docs for that schema, and
[Self-Hosting](/deployment/self-hosting) if you're not sure which mode you
want.

### Quick Setup with Docker

```bash
docker run -d \
  --name postgres \
  -p 5433:5432 \
  -e POSTGRES_USER=scrapix \
  -e POSTGRES_PASSWORD=scrapix \
  -e POSTGRES_DB=scrapix \
  -v pg_data:/var/lib/postgresql/data \
  postgres:17-alpine
```
