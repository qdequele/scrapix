# Map

The map endpoint discovers all URLs on a website using a sitemap-first strategy, with optional metadata fetching. It returns a structured list of URLs without crawling or indexing any content.

## POST /map

Discover URLs on a website. Scrapix first attempts to find and parse the site's sitemap(s), then optionally crawls to discover additional URLs up to the specified depth.

### Request Body

```json
{
  "url": "https://docs.example.com",
  "limit": 5000,
  "depth": 0,
  "search": "guide",
  "sitemap": true,
  "get_title": true,
  "get_description": true
}
```

### Parameters

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `url` | string | **required** | Base URL to discover URLs from |
| `limit` | integer | `5000` | Maximum number of URLs to return (at most `10000`) |
| `depth` | integer | `0` | Link-following depth (`0` = sitemap only, no crawling; at most `5`) |
| `search` | string | — | Keep URLs whose URL, title or description contains this text |
| `sitemap` | boolean | `true` | Whether to discover and parse sitemaps |
| `render_js` | boolean | `false` | Render pages in the browser before reading them (plans with JS rendering) |
| `get_title` | boolean | `true` | Fetch each page's `<title>` |
| `get_description` | boolean | `true` | Fetch each page's meta description |
| `get_lastmod` | boolean | `true` | Include `lastmod` from the sitemap |
| `get_priority` | boolean | `true` | Include `priority` from the sitemap |
| `get_changefreq` | boolean | `true` | Include `changefreq` from the sitemap |

### Response

```json
{
  "success": true,
  "links": [
    {
      "url": "https://docs.example.com/getting-started",
      "title": "Getting Started",
      "description": "Learn how to set up and configure the product",
      "lastmod": "2024-01-10T00:00:00+00:00",
      "changefreq": "weekly",
      "priority": 0.8
    },
    {
      "url": "https://docs.example.com/api-reference",
      "title": "API Reference"
    }
  ],
  "total": 247,
  "sitemaps": ["https://docs.example.com/sitemap.xml"],
  "duration_ms": 3120
}
```

### Response Fields

| Field | Type | Description |
|-------|------|-------------|
| `links` | array | Discovered URLs |
| `links[].url` | string | The discovered URL |
| `links[].title` | string | Page title (with `get_title`, when the page answered in time) |
| `links[].description` | string | Meta description (with `get_description`, when the page answered in time) |
| `links[].lastmod` | string | Last modification date from the sitemap |
| `links[].changefreq` | string | Change frequency from the sitemap |
| `links[].priority` | float | Priority from the sitemap (0.0 - 1.0) |
| `total` | integer | Number of URLs returned |
| `sitemaps` | array | The sitemaps the URLs were read from. Empty when the site has none (the URLs then come from the pages) |
| `duration_ms` | integer | Time the map took |

Fields without a value are omitted.

### How a map runs

1. **Sitemaps.** `robots.txt` is read at the site root, whatever the path
   of `url`, for its `Sitemap:` lines. Without any, the usual names are
   tried at the root: `sitemap.xml`, `sitemap_index.xml`,
   `sitemap-index.xml`, `sitemap.xml.gz`, `wp-sitemap.xml`. They are also
   tried when the declared sitemaps give no URL. When `url` has a path,
   `sitemap.xml` in its folder and in its first folder is read too
   (`/docs/sitemap.xml` for `/docs/guide/`). A sitemap can be XML, gzipped,
   a sitemap index, an RSS or Atom feed, or a text file with one URL per
   line; an HTML page served in its place is ignored. Sitemaps and the
   children of a sitemap index are fetched 8 at a time, and reading stops
   once about twice `limit` URLs are found.

   `example.com` and `www.example.com` are one site: when `robots.txt`
   redirects from one to the other, the sitemaps are looked up on the host
   the site answers on, and URLs on either host are kept. When the host
   does not answer at all, the other one is tried.

   When `url` has a path, the URLs under its folder come first, so `limit`
   keeps them; the rest of the site follows.
2. **Pages.** A page is fetched once at most: for its title and description,
   for its links (pages above `depth`), or both. When its links are not
   followed, only its `<head>` is kept and parsed. Pages start as soon as a
   slot is free; there is no wait between depth levels.
3. **Concurrency.** Fetches start at 32 at once and grow to 100 while the
   site keeps up. A `429`, a `503` or a timeout halves it (not below 4).
   Browser renders (`render_js`) run 50 at once.
4. **Time limits.** A page fetched only for its title and description has
   8 seconds and is not retried: a slow page goes without its title. A page
   whose links are followed has 30 seconds, one retry included (30 seconds
   too with `render_js`). The whole map, sitemaps included, stops after 60
   seconds and returns what it found by then.

### Use Cases

- **Pre-crawl planning** — discover URLs before starting a full crawl
- **Sitemap validation** — verify which URLs are listed in sitemaps
- **Content inventory** — list all pages on a site with titles and descriptions
- **Selective crawling** — use the `search` filter to find specific sections, then crawl only those

### Example

```bash
# URLs from sitemaps only: no page is fetched
curl -X POST http://localhost:8080/map \
  -H "Content-Type: application/json" \
  -d '{"url": "https://docs.example.com", "get_title": false, "get_description": false}'

# With titles and descriptions (the default)
curl -X POST http://localhost:8080/map \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://docs.example.com",
    "limit": 100
  }'

# Filter URLs containing "guide"
curl -X POST http://localhost:8080/map \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://docs.example.com",
    "search": "guide"
  }'
```

<Tip>
  With `depth: 0` (the default) and `get_title` and `get_description` set to `false`, a map reads only sitemaps and fetches no page: the fastest map. Titles and descriptions cost one fetch per URL. Increase `depth` to discover URLs not listed in sitemaps.
</Tip>
