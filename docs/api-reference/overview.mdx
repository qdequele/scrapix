# API Reference

The Scrapix API is a REST API built with [Axum](https://github.com/tokio-rs/axum) that manages distributed web crawling jobs, single-page scraping, and real-time event streaming.

## Base URL

```
http://localhost:8080
```

In production, replace with your deployment URL.

## Authentication

Self-hosted (standalone) engines require one operator key,
`SCRAPIX_ADMIN_KEY`, sent as `Authorization: Bearer <key>` or `X-API-Key:
<key>` (unless `SCRAPIX_AUTH=disabled`, local dev only). Hosted deployments
use per-account API keys and sessions instead — see the [Authentication
Guide](/guides/authentication) for the full standalone/hosted split.

## Request Format

All request bodies use JSON (`Content-Type: application/json`).

## Response Format

All responses return JSON. Successful responses return the data directly. Errors follow a consistent format:

```json
{
  "error": "Human-readable error message",
  "code": "machine_readable_code",
  "details": null
}
```

### Error Codes

| Code | HTTP Status | Description |
|------|-------------|-------------|
| `not_found` | 404 | Resource does not exist (or belongs to another account) |
| `bad_request` | 400 | Malformed request |
| `validation_error` | 400 | Invalid field values (e.g. a start URL that is not an absolute http(s) URL, an invalid `index_uid`) |
| `unauthorized` | 401 | Missing or invalid credentials |
| `insufficient_credits` | 402 | Not enough credits |
| `forbidden` | 403 | The caller's role cannot do this (viewers) |
| `spend_limit_exceeded` | 403 | The account's spend limit is reached |
| `analytics_unavailable` | 404 | `/analytics/v0/*` on a server without ClickHouse |
| `conflict` | 409 | The resource is in the wrong state (e.g. cancelling a finished job) |
| `quota_exceeded` | 429 | Plan limit reached (e.g. concurrent jobs) |
| `fetch_error` | 502 | The target page could not be fetched |
| `service_unavailable` | 503 | A dependency is unavailable (e.g. AI features without an AI provider); may carry `Retry-After` |
| `render_js_unavailable` | 503 | A browser feature on a server without a browser (see `GET /health/services`) |
| `timeout` | 504 | Operation timed out |

### Analytics

The Tinybird-style `/analytics/v0/pipes/*` API is served by the engine itself
against its ClickHouse, in both standalone and hosted mode (hosted callers
only see their own account). Without ClickHouse configured the routes return
`404` with `{"error": "Analytics unavailable", "code": "analytics_unavailable"}`. Engines also have `/stats`, `/errors` and `/domains` for in-memory
diagnostics (see [Diagnostics](/api-reference/diagnostics)).

## Rate Limiting

Per-account rate limiting by billing tier is a hosted-platform feature — see
**Rate Limiting** in the Platform docs for headers, 429 responses, and
handling. Standalone engines have no built-in per-request rate limiting;
throttle at your reverse proxy if you need it.

## OpenAPI & Interactive Docs

The API serves an OpenAPI 3.1 specification and interactive documentation:

- **`GET /openapi.json`** — Machine-readable OpenAPI spec (used by MCP server)
- **`GET /docs`** — Interactive API explorer powered by Scalar
