# Authentication

The engine's authentication depends on `SCRAPIX_MODE`.

## Standalone

A self-hosted engine (`SCRAPIX_MODE=standalone`, the default) is guarded by
one operator key: `SCRAPIX_ADMIN_KEY`. There are no per-user accounts, API
key CRUD, or sessions — every request either proves it knows the admin key
or is rejected.

### Sending the Key

Send the key as either header:

```bash
curl https://your-engine.example.com/jobs \
  -H "Authorization: Bearer $SCRAPIX_ADMIN_KEY"
```

```bash
curl https://your-engine.example.com/jobs \
  -H "X-API-Key: $SCRAPIX_ADMIN_KEY"
```

Both forms are checked in constant time and accepted interchangeably —
`Authorization: Bearer` is tried first, then `X-API-Key`. WebSocket routes
(`/ws`, `/ws/job/{id}`) additionally accept `?token=<SCRAPIX_ADMIN_KEY>` as a
query parameter, since a browser can't set a header on the upgrade request;
percent-encode the key (a raw `+` decodes to a space) and keep query strings
out of your reverse proxy's access logs.

### Protected vs Public Routes

| Public (no key required) | Protected (key required) |
|---------------------------|---------------------------|
| `GET /health` | `POST /scrape`, `/map`, `/search`, `/crawl`, `/crawl/sync`, `/crawl/bulk` |
| `GET /health/services` | `POST /batch/scrape`, `/extract`, `POST /parse` |
| `GET /metrics` | `GET /jobs`, `/job/{id}/*`, `DELETE /job/{id}` |
| `GET /openapi.json` | `GET /stats`, `/errors`, `/domains` |
| `GET /docs` | `GET /ws`, `/ws/job/{id}` |

### Error Response

A missing or invalid key returns `401`:

```json
{
  "error": "Missing or invalid admin key",
  "code": "unauthorized"
}
```

### Local Development: Disabling Auth

Setting `SCRAPIX_AUTH=disabled` turns off authentication for every route.
This is meant for local development only — the engine logs a loud warning
at startup, and refuses to start with `SCRAPIX_AUTH=disabled` in hosted
mode.

## Hosted

The hosted Meilisearch Lab platform uses per-account API keys and sessions
instead of a single admin key, plus OAuth 2.1 for MCP and third-party
clients — see **API keys** and **OAuth** in the Platform docs.

On the hosted engine, `/ws` and `/ws/job/{id}` also require authentication
(a `scrapix_session` cookie or Bearer token) — the console's live job
updates rely on `SESSION_COOKIE_DOMAIN` being set to a parent domain shared
with the API (e.g. `scrapix.meilisearch.com`, which covers
`api.scrapix.meilisearch.com`), so the browser can send the session cookie
on the WebSocket upgrade. `/stats`, `/errors` and `/domains` stay public in
hosted mode.
