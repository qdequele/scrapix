# Authentication

How you authenticate depends on how the engine is running.

## Standalone

A self-hosted engine (`SCRAPIX_MODE=standalone`, the default) is guarded by a
single operator key, `SCRAPIX_ADMIN_KEY` — there are no per-user accounts,
sessions, or API key management. Set it to a random string of at least 16
characters and send it on every protected request as either:

```
Authorization: Bearer <SCRAPIX_ADMIN_KEY>
```

or

```
X-API-Key: <SCRAPIX_ADMIN_KEY>
```

Browsers can't set headers on a WebSocket upgrade, so `/ws` and
`/ws/job/{id}` also accept the key as a `?token=` query parameter —
URL-encode it (a raw `+` decodes to a space) and strip or redact query
strings in your reverse proxy's access logs, since the key would otherwise
end up in plaintext log files.

For local development only, `SCRAPIX_AUTH=disabled` turns off auth entirely
(every route is unauthenticated); the engine logs a loud warning on startup
when this is set and refuses to start with it in hosted mode.

See [API Reference → Authentication](/api-reference/authentication) for the
exact request/response shapes, and [Self-Hosting](/deployment/self-hosting)
for the full setup.

## Hosted

The hosted Meilisearch Lab platform uses per-account API keys, sessions and
OAuth instead of a single admin key — see **API keys** in the Platform docs.
