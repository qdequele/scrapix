# Environment Variables

All Scrapix services are configured through environment variables. When running in single-binary mode (`scrapix all`), all variables apply to the single process.

## Deployment Mode & Authentication

| Variable | Default | Description |
|----------|---------|-------------|
| `SCRAPIX_MODE` | `standalone` | `standalone` (self-hosted, this repo's default) or `hosted` (behind the Meilisearch Lab control plane — [`meilisearch/lab`](https://github.com/meilisearch/lab) — reached over `LAB_URL`; the engine keeps its own database). Validated at startup — an unrecognized value refuses to start. See [Self-Hosting](/deployment/self-hosting). |
| `SCRAPIX_ADMIN_KEY` | — | **Standalone only.** The single operator key guarding every protected route (`Authorization: Bearer` or `X-API-Key`; WebSockets also accept `?token=`). Required unless `SCRAPIX_AUTH=disabled`; must be at least 16 characters (leading/trailing whitespace trimmed, blank-after-trim counts as unset). |
| `SCRAPIX_AUTH` | — | Set to `disabled` to turn off all authentication — **standalone only, local development only**. Logs a loud warning at startup; refused in hosted mode and refused together with `SCRAPIX_ADMIN_KEY` (conflicting config). |
| `DATABASE_URL` | `sqlite://./data/scrapix.db` | The engine's **own** job-history store, in both modes — SQLite by default, or a `postgres://`/`postgresql://` URL for a dedicated Postgres database (e.g. `scrapix_engine`). The engine applies its own migrations and refuses a database that already has the Rails schema, so it can never be pointed at the Lab's database. In hosted production use a dedicated Postgres database. |
| `JWT_SECRET` | — | Ignored by the engine (with a log line if set): the Lab verifies sessions. |

## Lab Boundary (hosted only)

In hosted mode the engine reports usage and job lifecycle to the Lab ([`meilisearch/lab`](https://github.com/meilisearch/lab)) as signed events and calls the Lab's `/internal/*` API (credential introspection, balance and plan limits, Meilisearch targets): see [Lab Events](/api-reference/lab-events). Every call carries the engine's instance identity. A standalone engine never talks to a Lab: `LAB_INSTANCE_ID`/`LAB_INSTANCE_SECRET` set on a standalone engine are refused at startup.

The hosted engine **refuses to start** without `LAB_URL`, `LAB_INSTANCE_ID`, `LAB_INSTANCE_SECRET` and `LAB_SERVICE_TOKEN`. At startup it calls `GET {LAB_URL}/internal/instances/me` and refuses to start on a `401` (wrong or revoked credentials: re-issue them on the Lab), a `404` (wrong `LAB_URL`, or a Lab that predates contract v2), or an instance the Lab does not describe as a hosted `scrapix` engine.

| Variable | Where | Default | Description |
|----------|-------|---------|-------------|
| `LAB_URL` | engine | none | **Required (hosted).** The Lab's base URL, e.g. `https://lab.meilisearch.com` (no path), as printed by the Lab's mint task. Events go to `{LAB_URL}/internal/events`; the rest of the boundary to `{LAB_URL}/internal/*`. |
| `LAB_INSTANCE_ID` | engine | none | **Required (hosted).** The uuid the Lab's operator minted for this deployment (`bin/rails lab:hosted_engine:create PRODUCT=scrapix REGION=... URL=... CREDENTIAL=<LAB_SERVICE_TOKEN>`, which prints `LAB_URL`, `LAB_INSTANCE_ID` and `LAB_INSTANCE_SECRET` once). Sent as `X-Lab-Instance-Id`. Refused in standalone mode. |
| `LAB_INSTANCE_SECRET` | engine | none | **Required with `LAB_INSTANCE_ID`.** 64 hex characters minted with the id. Bearer token on `/internal/*` calls, HMAC key on event batches. Rotate it with `bin/rails lab:hosted_engine:rotate ID=<LAB_INSTANCE_ID>` on the Lab; the old value stays valid for 10 minutes. |
| `LAB_SERVICE_TOKEN` | engine | none | **Required (hosted).** The token the Lab presents (with `X-Scrapix-Account-Id`) when it calls this engine for an account; at least 32 characters (`openssl rand -hex 32`). Generate it first: it is passed to the Lab at mint time as `CREDENTIAL=` (the Lab stores it per engine). The engine never sends it to the Lab. |
| `LAB_EVENTS_URL` | engine | none | **Deprecated.** Fallback for `LAB_URL` (the old `…/internal/events` URL). |
| `LAB_EVENTS_SECRET` | engine | none | **Deprecated, ignored** (warned at boot): batches are signed with `LAB_INSTANCE_SECRET`. |

<Note>
**Credential revocation is not instant.** The engine caches each credential's introspection answer for the `cache_ttl` the Lab returns (30 s by default, capped at 5 min), so a revoked or deleted API key keeps working on the engine for up to that long. While the Lab is unreachable, a credential that was valid is served stale for up to 5 more minutes, except answers with `cache_ttl` 0 (expired or expiring), which are never served stale. Lower the Lab's `cache_ttl` to shorten the window.
</Note>

<Note>
The Lab's own settings (Stripe, email, the saved-config cron, encryption keys, session secrets) are documented in the `meilisearch/lab` repo. The engine never talks to Stripe: it reports usage, and the Lab debits the ledger and runs auto top-up.
</Note>

## API Server

| Variable | Default | Description |
|----------|---------|-------------|
| `HOST` | `0.0.0.0` | API server bind address |
| `PORT` | `8080` | API server port |
| `ENABLE_CORS` | `true` | Enable CORS headers |
| `CORS_ORIGINS` | — | Comma-separated allowed CORS origins (optional, allows all when empty) |
| `MAX_JOBS` | `10000` | Maximum tracked jobs |
| `JOB_STALL_TIMEOUT_SECS` | `1800` | Seconds without progress before a job is finalized as `FailStalled` (stalled jobs are still billed for pages crawled) |
| `JOB_COMPLETION_GRACE_MS` | `3000` | Grace period after exact work accounting says a job is done, before finalizing it, to absorb straggler events |
| `RESUME_HEAL_AFTER_SECS` | `60` | A `Running` job whose work is not fully accounted for and that received no pipeline event for this long gets its `Resume` control re-published (self-heal of a lost or reordered Resume; a no-op for a job the frontier already runs). Rate-limited to one re-publish per job per 10 s |
| `MAX_PENDING_ACKS` | `50000` | Maximum event acks held while waiting for the accounting flush; the event consumer blocks (backpressure) at this cap until a flush frees room |
| `ALLOW_PRIVATE_IPS` | `false` | Allow webhook deliveries to reach private/loopback/link-local addresses (SSRF opt-out; same policy as the crawler's own `ALLOW_PRIVATE_IPS` — off by default, tests only) |
| `WEBHOOK_MAX_CONCURRENT_DELIVERIES` | `64` | Maximum webhook deliveries in flight at once, across all jobs and hooks |
| `CRAWL_BROWSER_AVAILABLE` | unset | Whether the crawler workers can render pages in a browser. Unset: unknown, `crawler_type: "browser"` crawls are accepted. `false`: `POST /crawl` refuses them (`503 render_js_unavailable`). Reported as `crawl_browser_available` by `GET /health/services`. `scrapix all` sets it from `BROWSER_RENDER` |

## Frontier Service

<Note>
Under `scrapix all` (single-process mode), `DOMAIN_DELAY_MS` and
`CONCURRENT_PER_DOMAIN` are hardcoded (`250`ms / `4`) and not read from the
environment. They're only tunable when the frontier runs as its own
service (distributed mode) — every other variable below applies in both
modes.
</Note>

| Variable | Default | Description |
|----------|---------|-------------|
| `DISPATCH_INTERVAL_MS` | `20` | Milliseconds between dispatch batches |
| `DISPATCH_BATCH_SIZE` | `2000` | URLs per dispatch batch |
| `DOMAIN_DELAY_MS` | `250` | Minimum delay between requests to same domain (jobs' `rate_limit` and robots.txt `Crawl-delay` can only raise it) |
| `BLOOM_CAPACITY` | `10000000` | **Deprecated and ignored.** Dedup now lives in the `FrontierStore` (Redis or in-memory), not a bloom filter; kept only so old env files don't fail to parse |
| `BLOOM_FP_RATE` | `0.01` | **Deprecated and ignored** (see `BLOOM_CAPACITY`) |
| `MAX_PENDING_PER_JOB` | `1000000` | Maximum pending URLs per job |
| `CONCURRENT_PER_DOMAIN` | `4` | Maximum concurrent requests per domain (a slot is held until the crawler reports the fetch back) |
| `REQUEST_TIMEOUT` | `30` | Crawler request timeout (s); a politeness slot without feedback expires after 2× this |
| `ROBOTS_DELAY_MULTIPLIER` | `1.0` | Multiplier applied to robots.txt `Crawl-delay` |
| `REDIS_URL` | — | When set, frontier state (dedup/queue via `FrontierStore`) and per-domain politeness state are shared in Redis across instances, so more than one frontier instance can run at once |
| `FRONTIER_KEY_PREFIX` | `scrapix:frontier` | Redis key prefix for the frontier store (only relevant with `REDIS_URL` set) |
| `JOB_RETENTION_HOURS` | `168` | How long a finished/cancelled job's counters and state stay queryable after its queue and seen set are released |
| `INSTANCE_ID` | random per start | Instance identifier. **Set a stable value per frontier instance in production**: it names the instance's job-control consumer group, so a random id loses controls published while the instance was down and leaks one consumer group per restart (a warning is logged when unset) |
| `DISPATCH_SHUTDOWN_GRACE_MS` | `10000` | On graceful shutdown, how long the dispatcher may take to finish its in-flight send and put every popped-but-unsent URL back into the store. Keep it below the platform kill timeout (Fly `kill_timeout` is 30 s) |
| `WAKE_PORT` | `8081` | Bare-TCP port serving `GET /metrics` and `GET /health`. On a single box give each service its own port (8081 is also the Lab's Rails port; a failed bind only logs a warning) |

<Note>
There is no separate `METRICS_PORT`. The engine (`scrapix-api`) serves
`GET /metrics` (Prometheus text format, unauthenticated) on its normal HTTP
port (`PORT`, default `8080`). Every worker (`scrapix-worker-crawler`,
`scrapix-worker-content`, `scrapix-frontier-service`) serves the same
`GET /metrics` and `GET /health` on its `WAKE_PORT` (default `8081`) — the
same bare-TCP listener Fly's proxy connects to for autostart. Metric names
are a contract with `qdq-server/monitoring`; see `crates/scrapix-core/src/metrics.rs`.
</Note>
