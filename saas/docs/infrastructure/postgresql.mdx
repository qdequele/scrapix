# PostgreSQL

PostgreSQL is **required** for the hosted platform. The Rails control plane
(`saas/`) owns this schema — user accounts, API key management,
authentication, saved configs, and engine registrations all live here.

<Note>
  This is the **Rails-owned** schema for the hosted platform. A self-hosted
  (standalone) engine can also use PostgreSQL for its own job store, but that
  is a completely separate, engine-owned schema — see PostgreSQL in the
  product docs' Infrastructure section. The engine refuses to start against
  a database that already has this Rails schema (and vice versa).
</Note>

## Quick Setup with Docker

```bash
docker run -d \
  --name postgres \
  -p 5433:5432 \
  -e POSTGRES_USER=scrapix \
  -e POSTGRES_PASSWORD=scrapix \
  -e POSTGRES_DB=scrapix \
  -v pg_data:/var/lib/postgresql/data \
  postgres:17-alpine
```

Then configure the Rails app:

```bash
export DATABASE_URL=postgres://scrapix:scrapix@localhost:5433/scrapix
export JWT_SECRET=change-this-in-production
```

## Applying the Schema

The schema is owned by the Rails app (`saas/db/migrate`, dumped to
`saas/db/structure.sql`) and applied with standard Rails tasks:

```bash
just infra                        # Starts PostgreSQL
cd saas && bin/rails db:prepare   # Creates/migrates the shared database
```

`just saas` (and the Docker Compose saas service) run `db:prepare`
automatically before starting the server. The engine (`bins/scrapix-api`)
never migrates this database — in hosted mode (`SCRAPIX_MODE=hosted`) it only
reads and writes rows in the schema the Rails migration created, and refuses
to start if the `jobs.accounting` column (or any other schema the current
engine expects) is missing.

## Database Schema

### Tables

**`users`** — User accounts

| Column | Type | Description |
|--------|------|-------------|
| `id` | UUID | Primary key |
| `email` | VARCHAR (unique) | Login email |
| `password_hash` | VARCHAR | Argon2 hash |
| `full_name` | VARCHAR | Display name |
| `created_at` | TIMESTAMPTZ | Registration date |
| `updated_at` | TIMESTAMPTZ | Last update |

**`accounts`** — Billing entities

| Column | Type | Description |
|--------|------|-------------|
| `id` | UUID | Primary key |
| `name` | VARCHAR | Account name |
| `tier` | ENUM | `free`, `starter`, `pro`, `enterprise` |
| `stripe_customer_id` | VARCHAR | Stripe integration |
| `created_at` | TIMESTAMPTZ | Creation date |

**`account_members`** — Account membership

| Column | Type | Description |
|--------|------|-------------|
| `user_id` | UUID | Foreign key to users |
| `account_id` | UUID | Foreign key to accounts |
| `role` | ENUM | `owner`, `admin`, `member` |

**`api_keys`** — API authentication tokens

| Column | Type | Description |
|--------|------|-------------|
| `id` | UUID | Primary key |
| `account_id` | UUID | Foreign key to accounts |
| `name` | VARCHAR | Key description |
| `prefix` | VARCHAR | Visible key prefix (e.g., `sk_live_...`) |
| `key_hash` | VARCHAR | SHA-256 hash of full key |
| `last_used_at` | TIMESTAMPTZ | Last API call |
| `created_at` | TIMESTAMPTZ | Creation date |

### Functions

- **`validate_api_key(key)`** — Validates an API key and returns the associated account with its billing tier
- **`update_updated_at()`** — Trigger function for automatic timestamp updates

## Kubernetes

The Scrapix Kubernetes base includes a PostgreSQL StatefulSet with the schema loaded via a ConfigMap init script:

```bash
kubectl apply -k deploy/kubernetes/base/
```

Production storage: 20Gi PVC.

## Managed Alternatives

| Service | Notes |
|---------|-------|
| [Neon](https://neon.tech) | Serverless Postgres, scale-to-zero. Great for low-traffic. |
| [Supabase](https://supabase.com) | Managed Postgres with extras. |
| [AWS RDS](https://aws.amazon.com/rds/postgresql/) | Managed Postgres on AWS. |
| [Fly Postgres](https://fly.io/docs/postgres/) | Fly.io managed clusters. |

Set `DATABASE_URL` on the Rails app to your managed PostgreSQL connection
string. The crawl engine does **not** share it: give it a separate database
(`scrapix_engine`) and set `SCRAPIX_MODE=hosted` and `LAB_URL` on every engine
instance.
